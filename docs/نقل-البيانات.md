# نقل البيانات — دفترُ تنفيذٍ محفوظ

> **مؤجَّلٌ بقرار صاحب المنصّة (٢٠٢٦-٠٩-٠٧).** المنصّةُ تعمل، والناسُ يحتاجونها،
> والنقلُ فائدتُه سرعةٌ لا وظيفة. يُنفَّذ في وقتٍ يختاره.
>
> وهذا الملفّ مكتوبٌ ليُقرأ بعد أسابيع بلا ذاكرة: كلُّ رقمٍ فيه مقيسٌ من
> القاعدة الحيّة يوم كُتب، وكلُّ خطوةٍ مرتَّبةٌ كما تُنفَّذ.

---

## لماذا

قاعدةُ البيانات في **سنغافورة** (`ap-southeast-1`). كلُّ طلبٍ من هاتفٍ في
الأنبار يقطع نصفَ الكوكب ذهاباً وإياباً، وذلك يُضاعف احتمالَ سقوطه على شبكةٍ
ضعيفة. والهدفُ **فرانكفورت** (`eu-central-1`) — لا منطقةَ لـSupabase في الشرق
الأوسط، وأوروبا هي أقربُ ما يُتاح، وطريقُ الإنترنت العراقيّ يمرّ بها أصلاً.

**والفائدةُ سرعةٌ لا وظيفة.** المنصّةُ تعمل اليوم؛ ولذلك يُختار وقتُ النقل
ولا يُستعجل.

البيانات. وبدونها كان النقلُ يعني خطأً أحمرَ أمام الناس طوالَ النافذة.

## الخطوة صفر — النسخة، وما لا وجود له إلا على الخادم

**تُنفَّذ ولو أُلغي النقلُ كلُّه.** المنصّةُ اليوم **بلا أيّ نسخةٍ احتياطيّة**،
والخطّةُ المجانيّة لا تعطي واحدة. هذه الخطوةُ قراءةٌ محضة، ومخرجُها أوّلُ نسخةٍ
ماديّةٍ تملكها.

### ١ ـ ما يُقرأ من الخادم أوّلاً

```sql
-- أمرا المهمّتين المجدولتين: موجودان على الخادم فقط.
-- الهجرةُ 20260821b_cron_of_record.sql:30-31 تُخفي جسمَيهما بـ$$ ... $$
select jobid, jobname, schedule, command, active, database, username
  from cron.job order by jobid;

-- عضويّةُ منشور القنوات الحيّة: على الخادم فقط كذلك،
-- ولا هجرةَ في المستودع تُنشئها (20260829_station_messages.sql:141 يقولها صراحة)
select schemaname, tablename from pg_publication_tables
 where pubname = 'supabase_realtime' order by 1,2;

-- المستودعُ ليس مصدرَ الحقيقة للمخطَّط — يُؤخذ الجدولُ الحقيقيّ
select table_name from information_schema.tables
 where table_schema = 'public' order by 1;

-- الامتدادات ومخطَّطُ كلٍّ (المخطَّطُ يهمّ: net.http_post يجب أن تُحَلّ)
select e.extname, e.extversion, n.nspname
  from pg_extension e join pg_namespace n on n.oid = e.extnamespace order by 1;

-- أدوارٌ خاصّة؟ إن لم تُرجع إلا أدوارَ Supabase القياسيّة فـroles.sql لا لزوم له
select rolname, rolcanlogin from pg_roles where rolname not like 'pg\_%' order by 1;

-- المُشغّلُ الذي يفتح الحسابات
select tgname, tgenabled from pg_trigger
 where tgrelid = 'auth.users'::regclass and not tgisinternal;

-- نسخةُ GoTrue — تُقارَن بالمشروع الجديد قبل الاستعادة
select version from auth.schema_migrations order by version desc limit 5;
```

### ٢ ـ البصمة — وهي المسطرة

```sql
select md5(string_agg(id::text || coalesce(email,'') || coalesce(encrypted_password,''),
                      '|' order by id)) as users_fp, count(*) from auth.users;
select md5(string_agg(id::text || user_id::text || provider || coalesce(provider_id,''),
                      '|' order by id)) as ident_fp, count(*) from auth.identities;
select count(*) from pg_policies where schemaname = 'public';
select public.health_counts();
```

هذه البصماتُ هي ما يُقارَن بعد الاستعادة. **وتطابقُها هو الإثباتُ الوحيد** أن
المعرّفاتِ والكلماتِ نجت حرفاً بحرف.

### ٣ ـ النسختان

```bash
supabase db dump --db-url "$OLD" -f schema.sql
supabase db dump --db-url "$OLD" -f data-dryrun.sql --use-copy --data-only \
  -x storage.buckets_vectors -x storage.vector_indexes -x public.notification_log
```

**تُنسخان إلى موضعين على الأقلّ خارج الحاسوب.**

## المرحلة الأولى — البروفة على مشروعٍ يُرمى

ثلاثةُ أسئلةٍ لا يجيبها التوثيق، ويجيبها التنفيذُ مرّةً واحدة.

> **قيدٌ يُرتَّب عليه:** الخطّةُ المجانيّة تسمح بمشروعين. القديم + البروفة =
> اثنان. فـ**يُحذف مشروعُ البروفة قبل إنشاء الهدف الحقيقيّ.**

يُنشأ المؤقّت في **`eu-central-1`** — المنطقةُ نفسُها، فيكون الزمنُ المقيسُ هو
الزمنَ المتوقَّع. وتُفعَّل الامتداداتُ من **لوحة Supabase** لا بـ`create
extension` بيد: مخطَّطُ `pg_net` الخاطئ يجعل `net.http_post` غيرَ قابلةٍ للحلّ
في أمر المهمّة، واللوحةُ تختار الصحيح.

```bash
psql --single-transaction -v ON_ERROR_STOP=1 -f schema.sql -d "$REHEARSAL"
psql --single-transaction -v ON_ERROR_STOP=1 \
     -c 'SET session_replication_role = replica' -f data-dryrun.sql -d "$REHEARSAL"
```

الفصلُ بين المخطَّط والبيانات مقصود: فشلُ البيانات لا يُلغي مخطَّطاً سليماً،
وفي التنفيذ الحقيقيّ يُحمَّل المخطَّطُ قبل النافذة بأيّام فلا يبقى على الساعة
إلا تحميلُ البيانات.

### ما يجب أن تجيبه البروفة

**١ ـ هل تكتمل الاستعادة أصلاً؟**
تُسجَّل كلُّ رسالة خطأ حرفيّاً. **ومخرجُ البروفة ملفُّ `schema.sql` منقّحٌ
يُعرف كلُّ سطرٍ غُيّر فيه ولماذا.** ولا يُعالَج خطأٌ بإسقاط `ON_ERROR_STOP`.

**٢ ـ هل نجت الحسابات حرفاً بحرف؟**
تُعاد بصمتا الخطوة صفر على البروفة. **يجب أن تتطابق النصوصُ تماماً.** وهذا
الفحصُ وحدَه يشمل المعرّفاتِ والعناوينَ وتجزئةَ كلمات المرور، وهو الوحيدُ الذي
يكشف تجزئةً أُعيد ترميزُها بصمت.

**٣ ـ وهل تدخل كلمةُ مرورٍ حقيقيّة فعلاً؟**
البصمةُ تُثبت البايتات، وهذا يُثبت أنّ النظامَ يقبلها:

```bash
curl -s -X POST "$REHEARSAL_URL/auth/v1/token?grant_type=password" \
  -H "apikey: $REHEARSAL_ANON" -H "Content-Type: application/json" \
  -d '{"email":"p<رقم معلوم>@muhta.app","password":"muhta<آخر أربعة>"}'
```

وكلمةُ المرور الافتراضيّة في `station-phone/index.ts:64` تعطي حساباً معلومَ
الكلمة بلا أن يُسأل أحد.

**٤ ـ هل نجا المُشغّل الذي يفتح الحسابات؟ (المتوقَّع: لا)**
`on_auth_user_created` مُشغّلٌ على `auth.users` (`schema.sql:39-41`)، و`auth`
مخطَّطٌ تديره Supabase و`db dump` يستثنيه افتراضاً.

**ولا يُكسر شيءٌ عند النقل** — كلُّ حسابٍ قائمٍ له صفُّ `profiles` سلفاً.
يُكسر **أوّلُ تسجيل محطةٍ جديدة بعده**: لا صفَّ `profiles`، فيسقط
`stations.owner_id` (`StationRegisterForm.tsx:185-220` يسجّل ثمّ يُدرج فوراً).
**وفحصٌ بحسابٍ قائمٍ لا يكشفه.**

فيُفحص وظيفيّاً لا بوجود المُشغّل — مُشغّلٌ موجودٌ معطَّلٌ يبدو كالعامل:

```bash
curl -s -X POST "$REHEARSAL_URL/auth/v1/admin/users" \
  -H "apikey: $REHEARSAL_SERVICE" -H "Authorization: Bearer $REHEARSAL_SERVICE" \
  -H "Content-Type: application/json" \
  -d '{"email":"probe@muhta.app","password":"probe123456","email_confirm":true}'
```
```sql
select count(*) from public.profiles where id = '<المعرّف المُعاد>';  -- يجب أن يكون ١
```

وإن كان صفراً فالإصلاحُ ستّةُ أسطرٍ من `schema.sql:39-41` تُنفَّذ بدور
`postgres` — **وتُكتب خطوةً صريحةً في الدفتر، لا تُكتشف في الإنتاج.**

**٥ ـ هل بقيت الصلاحيات؟**

```sql
select count(*) from pg_policies where schemaname = 'public';  -- يطابق الخطوة صفر
select table_name from information_schema.tables where table_schema='public' order by 1;
```

ثمّ الفحصُ الحقيقيّ: `scripts/probe-public.mjs` يمرّ على تسعة مسارات يقرؤها
الزائر. يُوجَّه `.env.local` إلى البروفة ويُشغَّل.

**٦ ـ الاستثناءُ عمل؟** `grep -c "COPY public.notification_log" data-dryrun.sql` → صفر.

**٧ ـ المتسلسلات.** `COPY` لا يُقدّمها، و`notification_log.id` من نوع
`bigserial`. يُشغَّل بعد كلّ تحميل:

```sql
do $$
declare r record; mx bigint;
begin
  for r in
    select c.oid::regclass::text tbl, a.attname,
           pg_get_serial_sequence(c.oid::regclass::text, a.attname) seq
      from pg_class c
      join pg_namespace n on n.oid = c.relnamespace
      join pg_attribute a on a.attrelid = c.oid and a.attnum > 0
     where n.nspname = 'public' and c.relkind = 'r'
       and pg_get_serial_sequence(c.oid::regclass::text, a.attname) is not null
  loop
    execute format('select coalesce(max(%I),0) from %s', r.attname, r.tbl) into mx;
    perform setval(r.seq, greatest(mx, 1));
  end loop;
end $$;
```

**٨ ـ هل عمل `session_replication_role = replica` فعلاً؟** يحتاج صلاحيّة، وسقوطُه
الصامتُ يجعل المُشغّلَ يعمل أثناء التحميل. يُتحقَّق: `show session_replication_role;`
على الاتّصال نفسِه.

**٩ ـ الزمن.** يُقاس تحميلُ البيانات بالساعة. **وهو المدخلُ الصادقُ الوحيد
لتقدير النافذة.**

ثمّ **يُحذف مشروعُ البروفة** — المقعدُ يحتاجه الهدف.

## المرحلة الثانية — بناءُ الهدف قبل النافذة بأيّام

لا شيءَ هنا يمسّ القديمَ ولا يراه أحد.

1. مشروع `muhta-eu` في **`eu-central-1`**، المنظّمة نفسُها.
2. **قبل أيّ استعادة:** تُقارَن نسخةُ GoTrue بالخطوة صفر. لو كان الجديدُ
   **أقدم** سقط التحميلُ بصوت؛ ولو كان **أحدث** فأعمدةٌ زائدةٌ تأخذ قيمَها
   الافتراضيّة — والمعرفةُ الآن خيرٌ منها في منتصف النافذة.
3. تُفعَّل الامتداداتُ الخمسة من اللوحة، وتُقارَن بالخطوة صفر بمخطَّطاتها.
4. يُحمَّل `schema.sql` المنقّح. ويُفحص المُشغّل ويُعاد إن لزم. وتُقارَن أعدادُ
   السياسات والجداول.
5. **إعداداتُ المصادقة باليد** — ليست في أيّ نسخة:
   التسجيلُ مفتوح · **تأكيدُ البريد مُطفأ** · أدنى كلمة ٦ أحرف · Site URL
   `https://muhta.online` · قائمةُ التوجيه.
   ثمّ يُتحقَّق بتسجيلِ حسابٍ حقيقيٍّ عبر الواجهة: جلسةٌ **وصفُّ `profiles`**، ثمّ يُحذف.
   > والتأكيدُ لو كان مُشغَّلاً لَقتل التسجيل: العناوينُ صناعيّةٌ ولا صندوقَ لها.
6. **تسعةَ عشرَ سرّاً.** واثنان فخّان يسقطان بلا رسالة:
   - `PRE_LAUNCH` — `telegram/index.ts:163` يقرؤها `?? '1'`. **غيرُ مضبوطةٍ تعني
     وضعَ ما قبل الإطلاق**، فيُغلق البوتُ على كلّ من ليس إدارة. تُضبط صراحةً.
   - **`VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` تُنسخان ولا تُولَّدان.** مفاتيحُ
     جديدة تُبطل كلَّ اشتراك دفعٍ في المتصفّح بصمت: الصفوفُ تُستعاد سليمةً
     وكلُّ إرسالٍ يردّ ٤٠٣. ويُنسخ `NEXT_PUBLIC_VAPID_PUBLIC_KEY` كما هو —
     يجب أن يساوي `VAPID_PUBLIC_KEY` وإلّا اشترك المتصفّحُ بمفتاحٍ لا يملكه المرسِل.
7. **تُنشر الأربعَ عشرةَ دالّةً كلُّها مع `supabase/config.toml`**:
   ```bash
   supabase functions deploy --project-ref <NEW>
   ```
   `config.toml` يحمل `verify_jwt = false`، وبدونه تردّ البوّابةُ ٤٠١ قبل أن
   تعمل الدالّة. **ولا يُستعمل `نشر-الدوال.bat`** — ينشر ستّاً من أربعَ عشرة
   ويثبّت المعرّفَ القديم في ثلاثة مواضع.
   > ولا تحتاج الدوالُّ تعديلاً: كلُّها تقرأ `Deno.env.get('SUPABASE_URL')`
   > وتحقنه المنصّةُ لكلّ مشروع.
8. يُستعاد منشورُ القنوات الحيّة من الخطوة صفر (`stations`، `station_products`،
   `traffic_votes`، `station_messages`، `site_stats`)، ويُقارَن.
9. **تُنشأ المهامُّ الأربعُ معطَّلة** بأمرِها الحرفيّ من الخطوة صفر بالمعرّف
   الجديد، ثمّ `update cron.job set active = false;`.
   > إنشاؤها قبل أيّام بلا ساعةٍ تجري يُخرج خطرَ الازدواج من النافذة كلِّها:
   > تبقى فيها جملةٌ واحدة (`active = true`) بدل أربعِ `cron.schedule` تُنشئ
   > نسخةً ثانيةً لو فُلتت واحدة — فيُرسَل كلُّ إشعارٍ مرّتين.
10. تُجهَّز أوامرُ تبديل أسرار GitHub الثلاثة **وأوامرُ إرجاعها**، مكتوبةً
    جاهزةً (`scripts/set-gh-secret.py`).
11. **تُفحص الدالّةُ `health` بجلسة إدارة قبل النافذة** — تُثبت APNs وFCM
    والموقعَ ورمزَ تلغرام ورمزَ GitHub أمام مزوّديها الحقيقيّين. كلُّ سرٍّ
    مكتوبٍ خطأً يظهر هنا، قبل أيّام.

## المرحلة الثالثة — النافذة

**تبدأ ٥:٠٠ فجراً. ويُتراجَع حتماً عند ٥:٤٠.**

> القطعُ الوطنيُّ السادسةَ صباحاً **يشمل المنفِّذ**. فما لم يكتمل قبلها بقي
> مكسوراً بلا عينٍ عليه حتى يعود الإنترنت. والقاعدةُ ليست تقديراً بل شرط.

| اللحظة | ما يقع |
|---|---|
| **ص+٠** | **تُوقَف الكتابةُ على القديم**: `update cron.job set active = false;` ثمّ `deleteWebhook` لتلغرام **بلا `drop_pending_updates`** — تلغرام يحفظ الرسائل ويعيدها عند تسجيل العنوان الجديد، فحركةُ البوت تتأخّر ولا تضيع. وكلاهما عكوسٌ بجملةٍ واحدة |
| **ص+١** | يُقلب مفتاحُ الصيانة، ويُنتظر النشر |
| **ص+٥** | يُتأكَّد من نافذةٍ خاصّة أن الشاشة ظهرت. وتُلتقط أعدادُ القديم — وهي مسطرةُ الفرق |
| **ص+٦** | `pg_dump` بلا `notification_log`. ثمّ `grep -c "COPY public.notification_log" data.sql` → صفر |
| **ص+١٠** | يُستعاد في الجديد بـ`--single-transaction` و`session_replication_role = replica` |
| **ص+١٤** | تُضبط المتسلسلات، ثمّ `update cron.job set active = true;` — ويُتحقَّق أنّ الصفوفَ **أربعة** بالضبط |
| **ص+١٥** | تُقارَن البصمتان بالخطوة صفر · `health_counts()` · `select count(*) from alerts` = ٥٧٬٣٠٤ |
| **ص+١٧** | **يُعاد عدُّ القديم.** أيُّ فرقٍ يعني كاتباً لم يُوقَف. فرقٌ في `traffic_votes` يُنقل باليد؛ فرقٌ في `alerts` أو `stations` يُوقف العمليّة |
| **ص+١٨** | **نقطةُ اللاعودة.** تُبدَّل أسرارُ GitHub الثلاثة · يُرفع مفتاحُ الصيانة إلى `false` · `setWebhook` لتلغرام بالمعرّف الجديد مع `secret_token` · ويُبدَّل عنوانُ Meta لواتساب |
| **ص+٢٣** | ينتهي النشر. وهذا البناءُ يقرأ **القاعدة الجديدة** في `generateStaticParams` |
| **ص+٢٥** | الفحص — بـ`?live=1` **قبل** أن تُرفع الصيانةُ عن الناس |

**التقدير: ٢٥ دقيقة. الميزانيّة: ٤٥. والحدُّ الأقصى: ٥:٤٠ مهما كان.**

ونصفُ الزمن نشرٌ (مرّتان × ٢–٤ دقائق) ولا يُقصَّر. والباقي بيانات (~٨٣ ميغابايت)
وتحقّق — والتحقّقُ هو أكبرُ حصّةٍ عمداً.

## الفحص بعد الفتح

**١ ـ هل بُنيت صفحاتُ المحطات فعلاً؟** — أخطرُ فشلٍ صامت:

```bash
curl -o /dev/null -w '%{http_code}\n' https://muhta.online/station/<معرّف معلوم>/
curl -o /dev/null -w '%{http_code}\n' https://muhta.online/station/none/   # يجب ٤٠٤
curl -s https://muhta.online/ | grep -o 'https://[a-z]*\.supabase\.co' | sort -u
```

`app/[slug]/page.tsx:23` يبتلع خطأ القراءة ويُخرج `[{slug:'none'}]`. فبناءٌ
**ناجح** بمفتاحٍ خاطئ يمحو كلَّ صفحات المحطات بلا شكوى في أيّ مكان. و
`/station/none/` يردّ ٢٠٠ هو العلامة. والمعرّفُ في الحزمة يجب أن يكون الجديدَ
وحدَه — القديمُ فيها يعني بناءً سبق تبديلَ الأسرار، فيُعاد النشرُ يدويّاً.

**٢ ـ قراءاتُ الزائر:** `.env.local` إلى الجديد، ثمّ `node scripts/probe-public.mjs`.

**٣ ـ الدفعُ يصل — ثلاثُ طبقات:**
- الصفوفُ وصلت: `select channel, count(*) from alerts group by 1;`
- **المفتاحُ هو القديم**: يُقارَن الظاهرُ في الحزمة بـ`.env.local` وبسرّ المشروع
  الجديد — الثلاثةُ متطابقة. وهذا ما يكشف مفتاحاً وُلّد من جديد، وإلّا بدا
  كلُّ شيءٍ سليماً حتى ينظر أحدٌ في ٤٠٣ لا يترقّبه
- **إرسالٌ حقيقيّ**: `test-push` إلى جهازك على القنوات الثلاث
- ثمّ السجلّ: `select kind, count(*), max(sent_at) from notification_log where sent_at > '<الفتح>' group by 1;`

**٤ ـ البوت:** `getWebhookInfo` — العنوانُ الجديد، و`pending_update_count` ينزل،
ولا `last_error_message`. و٤٠١ ثابتةٌ تعني أنّ `config.toml` لم يصل مع النشر.
ثمّ `/start` من حسابٍ غير إداريّ: لو ردّ بنصّ ما قبل الإطلاق فـ`PRE_LAUNCH` خطأ.

**٥ ـ المهامُّ تعمل مرّةً لا مرّتين:**

```sql
select jobname, count(*) from cron.job group by 1 having count(*) > 1;  -- فارغ
select j.jobname, r.status, r.start_time from cron.job_run_details r
  join cron.job j using (jobid) where r.start_time > now() - interval '15 minutes'
 order by r.start_time desc;
-- في عشر دقائق: notify-favorites خمساً، clear-stale-traffic مرّتين
select address, kind, sent_at, count(*) from notification_log
 where sent_at > '<الفتح>' group by 1,2,3 having count(*) > 1;   -- فارغ
```

> `owner-daily` يحميها فهرسُ `owner_pings`. و`notify-favorites` لا يحميها إلا
> نافذةُ الخمس والأربعين دقيقة في `alerts_for` — ومهمّتان متطابقتان تعملان في
> الثانية نفسِها قد تسبقانها.

**٦ ـ والكلُّ في نداءٍ واحد:** `health` بجلسة إدارة.

## نقلُ السجلّ — بعد الفتح بساعةٍ أو بيوم

لم يُكتب في `notification_log` القديم شيءٌ بعد ص+٠ (المهامُّ معطَّلة، والويب-هوك
مرفوع، والموقعُ في صيانة)، فمرّةٌ واحدةٌ بلا شرطٍ تكفي وتَصدُق.

```bash
psql "$OLD" -c "\copy (select address, kind, station_id, sent_at, title, body \
  from public.notification_log order by id) to 'history.csv' with (format csv)"
psql "$NEW" -c "\copy public.notification_log \
  (address, kind, station_id, sent_at, title, body) from 'history.csv' with (format csv)"
```

**ويُحذف `id` من النقل.** `bigserial` يعطي قيماً جديدة، فلا تصطدم بما كُتب بعد
الفتح، ولا حاجةَ إلى جراحةٍ في المتسلسلة — ولا شيءَ في المنصّة يشير إلى
`notification_log.id` (لا مفتاحَ أجنبيَّ داخلاً، والقارئان يرتّبان بـ`sent_at`).

والحدُّ الزمنيُّ يجعل النقلَ قابلاً للإعادة بأمان: كلُّ صفٍّ منقولٍ أقدمُ من
لحظة التجميد، وكلُّ صفٍّ حيٍّ أحدثُ منها.

```sql
select count(*) from notification_log where sent_at < '<بدء التجميد>';  -- ١٤٢٬٣٢٨
-- وإن انقطع النقل: delete ... where sent_at < '<بدء التجميد>'  ثمّ يُعاد
```

**وتبقى `rollup-notifications` معطَّلةً حتى يُتحقَّق من النقل** — هي تحذف ما
تجاوز ثلاثين يوماً، ولا يُراد تداخلُها مع `COPY`.

## التراجع

**قبل ص+١٨ — مجّانيٌّ وتامّ، خمسُ دقائق.** لم يتغيّر شيءٌ خارج المشروع الجديد.
يُعاد `active = true` على القديم، و`setWebhook` إلى المعرّف القديم، ويُرفع مفتاحُ
الصيانة. والقديمُ لم يُكتب فيه ولم يُغيَّر. ولا يُحذف الجديد — يُترك لمحاولةٍ
ثانية.

**بعد ص+١٨ وخلال ساعة — يُستعاد بدمجٍ يدويّ.** يُقلب المفتاح، وتُعطَّل مهامُّ
الجديد ويُرفع ويب-هوكُه، وتُرجَع أسرارُ GitHub، ويُعاد القديمُ كما كان. ثمّ
تُنقل الكتاباتُ التي وقعت في الجديد — وكلُّها محدودةٌ بلحظة الفتح وصغيرة:
`traffic_votes` · `station_messages` · `alerts` · `station_products` ·
`stations` · `device_tokens`.

**وما لا يُنقل نظيفاً: حساباتٌ جديدة** أُنشئت في تلك الساعة. الساعةَ الخامسةَ
فجراً هي على الأغلب صفر، **ويُتحقَّق صراحةً**:

```sql
select id, email, created_at from auth.users where created_at > '<الفتح>';
```

وأيُّ صفٍّ يُعاد إنشاؤه على القديم بواجهة الإدارة **بالمعرّف نفسِه** (تقبل
تحديدَه صراحةً)، وتُربط صفوفُه.

**وبعد نحو أربعٍ وعشرين ساعة لم يعد تراجعاً.** ولهذا كان الفحصُ كثيفاً في ص+٢٥
لا في صباح اليوم التالي.

**والقديمُ لا يُحذف ثلاثين يوماً.** ويتوقّف تلقائيّاً بعد سبعةٍ من الخمول —
وذلك عكوسٌ من اللوحة، لكنه يعني أنه ليس بديلاً فوريّاً بعد الأسبوع الأوّل.
**ولا يُنشأ مشروعٌ ثالثٌ في هذه المدّة**: حدُّ المشروعين سيُجبرك على حذف أحدهما،
وأحبُّهما إلى الحذف هو هدفُ تراجعك.

## ما لا يُفعل — على حسابٍ مجّانيٍّ بلا استرجاعٍ زمنيّ

1. **لا جملةَ هدمٍ واحدة على القديم.** المسموحُ فعلان عكوسان: `update cron.job
   set active = …` و`setWebhook`/`deleteWebhook`. لا `drop`، ولا `truncate`،
   ولا `alter`، ولا `pg_restore --clean`. **ولا استرجاعَ زمنيّ يُنقذ.**
2. **ولا تجميدٌ صلب** (`default_transaction_read_only`). يسدّ ثقباً حقيقيّاً —
   تبويبٌ مفتوحٌ قد يكتب في القديم أثناء النافذة — لكنه يضع إعداداً على **هدف
   التراجع نفسِه**، ونسيانُه يحوّل المخرجَ إلى عطل. وإعادةُ العدّ في ص+١٧ تكشف
   الشيءَ نفسَه بلا خطر، والضررُ الذي يمنعه بضعةُ أصواتِ ازدحامٍ الساعةَ الخامسة.
3. **ولا يُبدأ بلا نسختين على قرصين.** نسخُ الخطوة صفر هي النسخةُ الماديّةُ
   الوحيدة التي تملكها المنصّة.
4. **ولا يُولَّد ما يحمله جهازُ مستخدم**: VAPID، ورمزُ البوت، ومفتاحُ APNs.
   الصفوفُ تُستعاد سليمةً وكلُّ إرسالٍ يفشل بلا أن يشكوَ أحد.
5. **ولا يُنشر بـ`نشر-الدوال.bat`** في أيّ خطوةٍ من هذا كلِّه.
